# CYBER DUEL — AI 사이버 공격·방어 시뮬레이터

React + TypeScript + Vite 기반의 **한국어 사이버보안 교육용 턴제 게임**입니다. 고등학생이 보안 개념을 배우고, 허가된 가상 환경에서 선택의 결과를 비교하는 것이 목적입니다. 기존 홈, 사이드바, 아카데미 디자인과 GitHub Pages 배포 방식을 확장했습니다.

## 실행 방법

Node.js 22.12 이상, 권장 버전은 CI와 같은 **Node.js 24**입니다.

```sh
npm ci --cache /tmp/cyber-npm-cache
npm run dev -- --port 5173 --strictPort
```

작업 디렉터리는 저장소 루트입니다. 클라우드 체크아웃은 `/workspace/cyber`입니다. 화면은 `/cyber/` 경로에서 제공합니다.

```sh
npm run build       # TypeScript 검사 + dist/ 생성
npm test            # 엔진·저장·연구·튜터 자동 테스트
npm run preview -- --port 4173 --strictPort
```

다른 터미널에서 브라우저 통합 테스트를 실행할 수 있습니다. `playwright-core`는 브라우저를 자동 다운로드하지 않습니다. Chromium이 설치되어 있어야 합니다.

```sh
# 위 preview 서버를 실행한 상태에서
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
# 개발 서버를 대상으로 검사하려면
TEST_URL=http://127.0.0.1:5173/cyber/ npm run test:browser
```

브라우저 테스트는 전용 새 브라우저 세션에서 실행되어 개인 저장 기록을 건드리지 않습니다. 두 역할의 5단계 성공, 실패·재도전, 역할별 잠금, 새로고침 복원, 퀴즈·튜터, 별도 평가, 모바일 화면을 확인합니다. 실제 API나 서버 자격 증명은 필요하지 않습니다.

## 게임 방법

1. 홈에서 **게임 시작하기**를 누르고 RED TEAM 또는 BLUE TEAM을 선택합니다.
2. 1단계 학습 안내와 역할별 목표를 읽고 시뮬레이션을 시작합니다.
3. 행동 카드를 선택합니다. 한 행동마다 턴이 흐르고 규칙 기반 상대 AI가 반응합니다. 잠긴 행동은 선행 행동이 필요하거나 이미 사용했습니다.
4. 목표 증거를 검증하고 개선안을 보고합니다. 성공하면 **같은 역할의 다음 단계**가 열립니다. 실패해도 해설을 보고 다시 도전할 수 있습니다.
5. 보안 아카데미에서 관련 개념을 학습하고 연구 대시보드에서 탐지 규칙을 비교합니다.

| 단계 | 핵심 학습 | RED 관점 | BLUE 관점 |
| --- | --- | --- | --- |
| 1. 네트워크와 방화벽 | IP, 포트, 서비스, 허용/차단 | 노출된 관리 경로 증명 | 관리 경로 제한과 정상 웹 유지 |
| 2. 계정과 비밀번호 | 인증/인가, MFA, 계정 잠금 | 과도한 권한을 읽기 전용으로 증명 | 인증 강화와 권한 회수 |
| 3. 로그인 로그 | 간격, 실패 횟수, 오탐/미탐 | 합성 패턴의 탐지 공백 관찰 | 맥락 기반 규칙 적용·검증 |
| 4. SQL 인젝션 모형 | 입력/명령 분리, 최소 권한 | 가상 입력 경계 비교 | 매개변수화 모형과 정상 검색 검증 |
| 5. 복합 사고 대응 | 시간선, 격리, 복구, 보고 | 최소 영향 경로와 개선안 증명 | 증거 보존부터 복구·검증까지 수행 |

RED는 허가된 모형의 약점을 찾아 증명하고, BLUE는 정상 서비스를 보존하며 위험을 줄입니다. 두 역할은 목표와 행동, 필수 조건이 다릅니다. 행동마다 선행 조건·비용·결과가 있으며 조용한 조사와 빠른 시도, 좁은 차단과 넓은 차단 사이에 장단점이 있습니다.

성공에는 필수 증거·보고, 진행도 70 이상, 단서 30 이상, 가용성 25 이상이 필요합니다. 추가로 RED는 위험도 95 미만, BLUE는 보안 60 이상이어야 합니다. 위험도 100, 가용성 0, 제한 턴 초과는 실패입니다. 점수는 게임용으로 목표 달성 보너스, 진행도, 가용성, 단서, 낮은 위험도, 남은 턴을 반영합니다. 실제 보안 역량 측정 점수는 아닙니다.

상대 AI는 서버 API 없이 현재 상태, 직전 행동의 소음, 반복 여부, 보호 조치를 검사합니다. RED의 무리한 행동에는 감시를 강화하고, BLUE가 경로를 보호하면 공격 피해가 줄어듭니다. 생성형 AI나 실제 침투 도구가 아닙니다.

## 화면과 저장

- 기존 홈·프로젝트 소개·왼쪽 사이드바와 차콜/민트 디자인을 유지했습니다.
- 역할 선택, 5단계 선택, 학습 안내, 게임, 결과, 학습·연구 대시보드를 제공합니다.
- 플레이에는 가상 노드 지도, 목표·상태 지표, 행동 카드, AI 반응, 턴별 이벤트, 힌트, 모의 터미널이 있습니다.
- 터미널은 `help`, `status`, `map`, `logs`, `rules`만 텍스트로 처리합니다. 입력으로 운영체제 명령, JavaScript, 외부 요청을 실행하지 않습니다. 터미널 조회는 턴을 소모하지 않습니다.
- `localStorage`의 `cyber-duel:v1`에 일시 정지한 게임 1개, 역할별 결과, 퀴즈 답변을 저장합니다. 최고 점수는 저장한 기록에서 계산합니다. 기기/브라우저 간 동기화는 없습니다.
- 홈의 이어하기와 새로고침 복원을 지원합니다. 새 미션 시작 시 이전의 진행 중 게임 1개는 대체하며 완료 기록은 유지합니다. 결과 화면 자체는 새로고침 후 단계 선택으로 돌아가지만 완료 기록은 남습니다.
- 저장 실패·손상 기록은 한국어로 안내하며 현재 탭에서는 계속 플레이할 수 있습니다. 퀴즈 진도는 현재 정답을 선택한 개념 수입니다.
- 키보드 포커스, 본문 건너뛰기, 상태 안내, 표의 설명, 모바일 메뉴를 제공합니다.

## 아카데미와 교육적 의의

12개 개념을 **비유 → 정확한 설명 → 게임 사례 → 퀴즈**로 제공합니다. 네트워크/IP/포트, 서비스, 방화벽, 인증/인가, 비밀번호/MFA, 로그, 해시/암호화, SQL 인젝션, XSS, 피싱, 접근 제어, 사고 대응을 다룹니다. 오답과 정답 모두 이유를 확인하고 다시 선택할 수 있습니다.

보안은 공격을 많이 막는 것만이 아니라 정상 업무와 증거를 보존하는 판단이라는 점을 학습합니다. 실패 후 행동별 결과를 돌아보고 다른 선택으로 재도전하도록 설계했습니다.

### 데모 튜터와 향후 Gemini 연동

현재 튜터는 **미리 작성한 로컬 자료를 검색하는 데모**입니다. 생성형 AI의 답변인 것처럼 표시하지 않습니다. 예시 질문과 자유 입력 UI는 작동하며 알 수 없는 질문에는 지원 범위를 안내합니다. 채팅 내용은 현재 탭에만 있으며 API 키 입력 기능은 없습니다.

`src/tutor.ts`의 `TutorProvider` 인터페이스가 답변 제공자를 분리합니다. 향후 Gemini 연동에는 사용자 인증, 사용량 제한, 요청 검증, 비밀 관리가 있는 백엔드 또는 적절한 서버리스 중계가 필요합니다. 키는 서버 측 비밀 저장소에서 관리하거나 사용자 키를 사용할 경우 인증된 보안 경로와 일시적 메모리 처리 방식을 별도 설계해야 합니다. 키를 공개 프런트엔드 번들·GitHub·localStorage·로그에 넣거나 공개 프록시를 만들면 안 됩니다. 현재 핵심 게임과 학습 기능은 유료 API 없이 모두 동작합니다.

## 심화탐구 설계

한 데이터 행은 가상 출발지의 **5분 로그인 관측 구간**입니다. 정상/급격한 공격/느린 분산 공격 라벨과 실패 횟수, 평균 간격, 계정 수, 야간 여부를 합성합니다. 실제 로그인 요청은 보내지 않습니다.

- 생성기 v1: 32비트 LCG, `state = (1664525 × state + 1013904223) mod 2^32`.
- 조정용 120행은 입력 시드, 평가용 120행은 `seed XOR 0x9e3779b9`의 독립 스트림으로 생성합니다. 시드 0도 유효합니다.
- 정상/급격/느린 패턴은 각각 약 60/20/20% 확률입니다. 특징 범위와 야간 확률은 연구실의 생성 규칙에 표시합니다. 각 구간은 최소 2회 이상 시도하며 실패 수와 계정 수 이상으로 시도 수를 정합니다. 간격은 5분 구간에 들어오도록 제한하고, 새벽 2시 또는 오후 2시를 시작으로 실패 이벤트 후 성공 이벤트를 생성합니다. 계정은 순환 배정하며 특징은 원시 이벤트에서 다시 집계합니다. 정상 데이터 일부도 반복 실패를 포함하여 오탐을 관찰합니다.
- 규칙 A: 실패 횟수 임계값. B: 실패 횟수와 (짧은 간격 또는 여러 계정). C: 실패×0.45 + 계정×0.65 + 짧은 간격 2점 + 야간 1점의 가중치 점수입니다. C는 학습된 머신러닝 모델이 아닙니다.
- 조정용 데이터에서 임계값을 선택하고 확정한 뒤 별도 평가를 실행합니다. 평가 후 슬라이더가 잠겨 같은 화면에서 평가 수치를 보며 조정하지 못하도록 합니다.
- TP/FP/TN/FN, 정밀도(precision), 재현율(recall), 오탐률(FPR), F1을 실제 데이터로 계산합니다. 혼동행렬·F1 막대·패턴별 탐지율·실험 비교 표를 제공합니다. 분모가 0이면 0으로 표시합니다. 전체 정확도(accuracy)와 정밀도는 다른 개념입니다.
- 실험 비교 기록은 현재 탭에서 최근 8개이며 페이지를 떠나거나 새로고침하면 초기화됩니다. **시드·규칙·결과 JSON 저장**으로 조정/평가 원시 이벤트, 특징, 임계값, 가중치와 결과를 내려받을 수 있습니다. 같은 시드·설정으로 실험을 재현할 수 있습니다.

합성 데이터는 라벨과 특징의 관계를 우리가 정했으므로 실제 보안 환경보다 단순합니다. 평가 결과를 본 뒤 같은 시드로 재조정하면 여전히 과적합 위험이 있습니다. 사전에 분리한 새 시드와 데이터에서 확인해야 합니다. 이 실험으로 실제 공격 탐지 성능을 보장할 수 없습니다.

## 기술 구조와 한계

- React 19 / TypeScript 5 / Vite 7 / lucide-react. 테스트는 Node 테스트 러너 + tsx, 브라우저 검증은 playwright-core + Chromium입니다.
- `src/game/engine.ts`: 공통 상태 전이, AI 반응, 성공/실패와 점수.
- `src/game/missions.ts`: 5개 미션의 초기 상태, 역할별 목표, 행동, 조건, 힌트, 해설.
- `src/game/storage.ts`: 저장, 역할별 잠금 해제, 모의 터미널.
- `src/GameUI.tsx`, `src/Academy.tsx`, `src/Research.tsx`: 게임·학습·연구 화면.
- `src/research.ts`: 재현 가능한 생성기와 탐지 지표. `src/tutor.ts`: 데모 제공자 인터페이스.

게임은 추상화한 상태 지표와 정해진 규칙으로 동작합니다. 네트워크 스택, 실제 DB, 실제 공격 코드, 실제 방화벽 설정을 구현하지 않습니다. SQL 단계는 상태 기반 미션과 입력 비교 보조도구를 제공합니다. 정상 입력과 교육용 조건 토큰을 넣으면 취약 모형과 매개변수 모형이 반환하는 모의 행이 달라집니다. 길이 검증을 켜서 입력 검증만으로는 충분하지 않은 이유도 확인할 수 있습니다. 실제 SQL 엔진은 없습니다. 탐지 연구실은 합성 로그의 별도 실험이며 미션 점수와 실제 탐지 지표를 혼동하지 않도록 분리했습니다.

## GitHub Pages

Vite의 기본 경로는 `/cyber/`입니다. 해시 라우팅을 사용하여 하위 화면에서 새로고침해도 서버의 별도 경로 처리가 필요하지 않습니다.

### 한 번만 하는 저장소 설정

1. GitHub 저장소에서 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택하세요. 이 설정은 코드 파일만으로 바뀌지 않으며 저장소 관리자 권한이 필요합니다.
2. 저장소의 **Actions** 사용이 허용되어 있는지 확인하세요.
3. PR을 `main`에 병합하세요. **Actions → Deploy to GitHub Pages**에서 성공 여부를 확인할 수 있습니다. 이미 코드가 `main`에 있다면 **Run workflow**에서 `main`을 선택하여 실행할 수도 있습니다.

배포 성공 후 주소는 https://victorianov09-commits.github.io/cyber/ 입니다. 실제 배포가 완료되기 전에는 페이지가 열리지 않을 수 있습니다.

### 자동 배포가 진행되는 방식

- `main` 대상 PR: `npm ci`로 잠금 파일에 맞게 설치하고 `npm run build`로 TypeScript 검사와 빌드를 실행합니다. PR에서는 사이트를 배포하지 않습니다.
- `main`에 push 또는 PR 병합: 같은 빌드 검사를 통과한 `dist/`를 GitHub Pages에 배포합니다.
- 수동 실행: `main`에서 **Run workflow**를 실행하면 빌드 후 배포합니다. 다른 브랜치는 빌드만 실행합니다.
- 배포 작업에만 Pages 쓰기 권한과 인증 권한을 부여합니다.

저장소 이름을 바꾸면 `vite.config.ts`의 `base`도 바꿔야 합니다.
